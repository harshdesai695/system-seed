# 🎯 What is Blob Storage?

**Blob (Binary Large Object) Storage** is a service for storing massive amounts of unstructured data — images, videos, documents, backups, logs — as binary objects. Unlike databases, blob storage is optimized for storing and retrieving large files cheaply at scale.

<Callout type="tip" title="Real-World Analogy">
  Blob storage is like a **self-storage warehouse**. You rent a unit (bucket/container), put boxes (blobs) in it with labels (keys), and retrieve them later. You don't care how the warehouse organizes things internally — you just need your stuff back when you ask for it.
</Callout>

---

## 🌍 Real-World Example

**Netflix** stores all its video content in **Amazon S3** (blob storage). Each movie is encoded in dozens of formats/resolutions and stored as blobs. When you press play, the CDN fetches the right blob from S3 based on your device and bandwidth.

## 🔍 How Blob Storage Works

### Architecture Layers

1. **Client API** — PUT/GET/DELETE objects via HTTP
2. **Metadata Service** — Maps keys to storage locations (uses a database)
3. **Storage Nodes** — Actual machines with disks storing the binary data
4. **Replication** — Each blob is replicated across multiple nodes/data centers

### Key Operations

| Operation | Description |
|-----------|-------------|
| **PUT** | Upload a blob with a unique key |
| **GET** | Retrieve a blob by its key |
| **DELETE** | Remove a blob |
| **LIST** | List all blobs in a bucket |
| **HEAD** | Get metadata without downloading |

| **Durability** | 99.999999999% (11 9's) | 99.999999999% | 99.999999999% |
| **Storage Tiers** | Standard, IA, Glacier | Hot, Cool, Archive | Standard, Nearline, Coldline |

| **Access Control** | IAM + Bucket Policies | RBAC + SAS tokens | IAM + ACLs |

## ⚖️ Pros & Cons

| Pros ✅ | Cons ❌ |
|---------|---------|
| Unlimited scalability | No query/search capabilities |
| Very cheap for large files | Higher latency than databases |
| Built-in durability (11 9's) | Eventual consistency in some configs |
| Simple key-value API | Not suited for small structured data |

---

## 🧩 When to Use

- **Use when:** Storing images, videos, backups, logs, static assets, data lake storage
- **Avoid when:** You need fast queries, transactions, or structured data relationships

## 📝 Quick Quiz

**Q1: Your app stores user profile pictures. Should you store them in a PostgreSQL column or blob storage?**

A) PostgreSQL BYTEA column  B) Blob storage (S3) with URL reference in DB

**Answer: B** — Blob storage is purpose-built for binary files. Store the blob in S3 and keep just the URL/key in the database. This keeps your DB small and fast.
