# 🎯 What is Distributed Tracing?

**Distributed tracing** tracks a request as it flows through multiple services in a distributed system. It creates a **trace** — a tree of spans representing each service call — giving you end-to-end visibility into request latency, errors, and dependencies.

<Callout type="tip" title="Real-World Analogy">
  Like a **package tracking system** (FedEx, UPS). When you ship a package, you get a tracking number. At every checkpoint (warehouse, truck, customs, delivery), its timestamp is logged. You can see exactly where it is, how long each step took, and where delays occurred. Distributed tracing does this for requests.
</Callout>

---

## 🌍 Real-World Example

**Uber** uses **Jaeger** (which they created) to trace requests across their 4,000+ microservices. When a ride request takes too long, engineers can see the exact trace — "API Gateway → Matching → Pricing → Payment → Notification" — and identify that the Pricing service added 2 seconds of latency.

---

## 🔍 Key Concepts

| Term | Description |
|------|-------------|
| **Trace** | The complete journey of a request through all services |
| **Span** | A single operation within a trace (one service call) |
| **Trace ID** | Unique identifier that follows the request everywhere |
| **Span ID** | Unique identifier for each individual span |
| **Parent Span** | The span that initiated the current span |
| **Context Propagation** | Passing trace/span IDs across service boundaries |
| **Baggage** | Key-value pairs carried alongside the trace context |

## ⚖️ Pros & Cons

| Pros ✅ | Cons ❌ |
|---------|---------|
| End-to-end request visibility | Performance overhead from instrumentation |
| Pinpoint latency bottlenecks | Storage cost for trace data |
| Understand service dependencies | Requires instrumentation in every service |
| Debug production issues fast | Sampling may miss rare issues |

---

## 🧩 When to Use

- **Use when:** Microservice architectures, debugging latency issues, understanding service dependencies
- **Avoid when:** Monolithic applications (standard logging/profiling suffices)

## 📝 Quick Quiz

**Q1: A user reports that checkout takes 8 seconds. You have 12 microservices involved. How do you find the bottleneck?**

A) Add logging to each service  B) Look at the distributed trace for the request

**Answer: B** — A distributed trace shows the exact duration of each span. You'll immediately see which service is taking 6 seconds of the total 8.
