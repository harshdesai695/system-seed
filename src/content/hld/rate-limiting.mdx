# 🎯 What is Rate Limiting?

**Rate Limiting** controls how many requests a user or client can make to a service within a given time window. It protects systems from being overwhelmed.

<Callout type="tip" title="Real-World Analogy">
  Think of a **theme park** that only lets 100 people in per hour. Once the limit is reached, newcomers must wait. This prevents overcrowding and ensures everyone inside has a good experience.
</Callout>

---

## 🌍 Real-World Example

**Twitter/X API** limits requests to 15 per 15-minute window for most endpoints. **GitHub API** allows 5,000 requests per hour for authenticated users. **Stripe** limits API calls to 100/second per account. These limits prevent abuse and ensure fair usage.

## Common Algorithms

### 1. Token Bucket
A bucket holds tokens. Each request consumes one token. Tokens are added at a fixed rate. If the bucket is empty, requests are rejected.

### 2. Sliding Window Log
Track timestamps of all requests. Count requests in the current window. Reject if count exceeds the limit.

### 3. Fixed Window Counter
Count requests in fixed time windows (e.g., per minute). Reset the counter when the window expires.

### 4. Sliding Window Counter
Combines fixed window and sliding window. Uses weighted counts from current and previous windows.

---

## 📊 Algorithm Comparison

| Algorithm | Accuracy | Memory | Burst Handling |
|-----------|:---:|:---:|:---:|
| Token Bucket | Good | Low | Allows controlled bursts |
| Sliding Window Log | Exact | High | No bursts |
| Fixed Window | Approximate | Very Low | Edge-of-window bursts |
| Sliding Window Counter | Good | Low | Smooth limiting |

            tokens -= 1;
            return true;  // ✅ Request allowed
        }
        return false;  // ❌ Rate limited

    private void refill() {
        long now = System.nanoTime();

        lastRefillTime = now;

## ⚖️ Pros & Cons

| Pros ✅ | Cons ❌ |
|---------|---------|
| Prevents system overload | Legitimate users can be blocked |
| Protects against DDoS attacks | Adds latency for limit checking |
| Ensures fair resource usage | Complexity in distributed rate limiting |
| Cost control (API billing) | Hard to set the right limits |

## 📝 Quick Quiz

**Q1: Your API gets 1000 requests/second normally but spikes to 5000 during events. Which algorithm handles bursts best?**

A) Fixed Window  B) Token Bucket  C) Sliding Window Log

**Answer: B** — Token Bucket allows controlled bursts up to the bucket capacity, then smoothly rate limits.
